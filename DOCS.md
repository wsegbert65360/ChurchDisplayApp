# ChurchDisplayApp - Docs

This document covers installation, build steps, and day-to-day operation for the current ChurchDisplayApp program.

## System Requirements

- Windows 10 or Windows 11, 64-bit
- A second monitor or projector is recommended
- Visual C++ 2015-2022 Redistributable x64 for VLC native playback
- For development: .NET SDK capable of building `net8.0-windows`
- For installer builds: Inno Setup 6

Self-contained release builds include the .NET runtime and VLC native package files.

## Installation

ChurchDisplayApp is distributed as a Windows installer generated by Inno Setup.

1. Run `ChurchDisplayApp-{version}-Setup.exe`.
2. Follow the installer prompts.
3. Launch the app from the desktop or Start Menu shortcut.
4. Connect the projector or second display before starting service when possible.

The installer checks for the Visual C++ Redistributable and creates Windows firewall rules for the remote control ports `8088` and `8090`.

## Building

### Recommended Release Build

Run from the project root:

```powershell
.\sync-fcc.bat
```

This script publishes the app, builds the installer, and can sync the installer to a deployment folder when configured.

### Manual Build

```powershell
dotnet build ChurchDisplayApp.csproj -c Release
dotnet publish ChurchDisplayApp.csproj -c Release -r win-x64 --self-contained true
```

Published files are written under `bin\Publish\win-x64\`. The installer script reads from that folder.

### Installer

The installer definition is `ChurchDisplayApp.iss`.

Output format:

```text
bin\Installer\ChurchDisplayApp-{version}-Setup.exe
```

The version comes from the published `ChurchDisplayApp.exe`.

## Basic Operation

### Startup

On launch, the app loads settings and starts VLC initialization in the background. The main window shows a loading overlay until the media engine is ready.

When ready, the app creates the live output window. If multiple monitors are available, the app prompts for the display monitor and positions the live output there.

### Add Media

Use **ADD MEDIA** or drag supported media files into the playlist.

Supported files:

- Images: `.jpg`, `.jpeg`, `.png`, `.bmp`, `.gif`
- Video: `.mp4`, `.mov`, `.wmv`, `.mkv`
- Audio: `.mp3`, `.wav`, `.flac`, `.wma`, `.m4a`

### Play Media

You can start playback by:

- Double-clicking a playlist item
- Selecting an item and pressing Play
- Using the remote playlist
- Using keyboard shortcuts

The live output window shows the media on the selected display. The operator window shows a live preview.

### Volume

The app currently has one operator-facing media volume slider.

Each playlist item stores a volume value. When an item starts playing:

1. The item's volume is applied before playback.
2. The main volume slider updates to that value.
3. Slider changes are written back to the currently loaded playlist item.
4. Saved playlists preserve those item volumes.

The service elements window also has a default service volume. That value is used when adding new service items unless a slot-specific volume override is set.

### Stop And Blank

- **Stop** stops playback, clears the output, resets progress, and clears the active media path.
- **Blank** hides the projected content without forgetting the current media path, so playback can be resumed.

### Amen

The **AMEN** button stops current media and plays the Amen resolve chord using the bundled SoundFont. The same action is available from the remote control page.

### Playlist Files

Use **SAVE PLAYLIST** and **LOAD PLAYLIST** to persist service playlists.

Current playlist format:

```json
{
  "version": 2,
  "items": [
    {
      "fullPath": "C:\\Media\\song.mp4",
      "volume": 1.0
    }
  ]
}
```

Legacy playlists that are JSON arrays of path strings still load. Missing or unsupported media files are skipped during load.

### Close Playlist

If the playlist has unsaved changes, **CLOSE PLAYLIST** prompts:

- Yes: save first, then close
- No: close without saving
- Cancel: return to the playlist

## Service Elements

Use **NEW PLAYLIST** to open the service elements window.

Service element slots can:

- Select a media file
- Clear a media file
- Add one item to the playlist
- Add all valid selected service elements
- Remember a selected file between sessions
- Use a slot-specific volume override or the global default service volume

Non-remembered slots are cleared when the service elements window opens.

## Remote Control

The app displays a QR code and URL in the operator window after the remote server starts.

Remote controls include:

- Playlist item selection
- Play
- Pause
- Stop
- Amen
- Volume up/down
- Volume slider
- Mute/restore
- Progress display

The remote server uses port `8088` by default and falls back to `8090` if needed.

## Keyboard Shortcuts

- Space: play/pause
- Right arrow: next playlist item
- Left arrow: previous playlist item
- B: blank output
- F11: toggle fullscreen
- Escape: exit fullscreen

## Configuration Files

Settings are stored at:

```text
%APPDATA%\ChurchDisplayApp\settings.json
```

The app remembers:

- Main media volume
- Default service volume
- Playlist font size
- Sidebar width
- Last media folder
- Last playlist folder
- Service element slots
- Optional VLC audio device override

## Troubleshooting

### Media Engine Fails To Load

Install or repair the Visual C++ 2015-2022 Redistributable x64, then restart the app.

### Remote Page Does Not Load

Confirm the phone/tablet is on the same network as the computer. Check the URL shown beside the QR code. If port `8088` is unavailable, the app may use `8090`.

### Playlist Loads With Fewer Items Than Expected

The loader skips files that no longer exist or use unsupported extensions. Re-add those files from their current location.

### Settings Did Not Persist

Most settings save on a short debounce. Shutdown also forces a save for critical state. If settings still do not persist, check write access to `%APPDATA%\ChurchDisplayApp`.
