# Remove Master Volume — Per-Item Volume Fix Plan

## Problem Statement
The app maintains a separate "master volume" (`_volume` in `MainViewModel`, persisted as `AppSettings.MainMediaVolume`) alongside per-item volumes in `PlaylistItem.Volume`. This dual-track design causes the slider and actual playback volume to diverge when switching media. The user has confirmed: **there should be no master volume; each playlist item has its own volume (0–100%)**.

## Root Cause
- `MainViewModel._volume` acts as a global volume that can drift from the active item's `PlaylistItem.Volume`.
- When switching media, `PlaySelected` must manually sync `Volume = SelectedItem.Volume`. If this sync is skipped, stale, or encounters a silent `SetProperty` no-op (same value), the slider and/or playback use the wrong level.
- `AppSettings.MainMediaVolume` persists a global value that has no meaning in a per-item model.

## Solution Overview
Remove the master volume entirely. Make `MainViewModel.Volume` a **computed property** that reads from and writes directly to the active item (`_currentlyLoadedPath` if present, otherwise `SelectedItem`). There is no backing field; the source of truth is always the `PlaylistItem`.

## Files to Change

### 1. `ViewModels/MainViewModel.cs`
- **Remove** field `private double _volume = 0.5;`
- **Change** `Volume` property:
  - `get`: if `_currentlyLoadedPath` is set, find that item in the playlist and return its `Volume`; else return `SelectedItem?.Volume ?? _settings.DefaultServiceVolume`.
  - `set`: clamp to `0.0–1.0`, compare against current `get` value (skip if no change > 0.001), then:
    - call `_mediaControlService.SetVolume(value)`;
    - if `_currentlyLoadedPath` is set, find the loaded item and write its `Volume`;
    - else if `SelectedItem != null`, write to `SelectedItem.Volume`;
    - raise `OnPropertyChanged(nameof(Volume))` and `OnPropertyChanged(nameof(VolumePercentage))`.
- **Change** `VolumePercentage` to use `Volume` getter instead of `_volume`.
- **Constructor**: remove `_volume = _settings.MainMediaVolume` and `_mediaControlService.SetVolume(_volume)`. No volume init call needed — it will be applied per-item at play time.
- **`SelectedItem` setter**: add `OnPropertyChanged(nameof(Volume))` and `OnPropertyChanged(nameof(VolumePercentage))` alongside the existing property notifications.
- **`Stop()`**: add `OnPropertyChanged(nameof(Volume))` and `OnPropertyChanged(nameof(VolumePercentage))` after clearing `_currentlyLoadedPath`, so the slider snaps to the selected item's volume (or default) after stopping.
- **`PlaySelected` (new media)**: remove `Volume = SelectedItem.Volume;` (line 213). After setting `_currentlyLoadedPath`, raise `OnPropertyChanged(nameof(Volume))` and `OnPropertyChanged(nameof(VolumePercentage))` so the slider updates from the computed getter.
- **`PlaySelected` (resume path)**: remove `Volume = SelectedItem.Volume;` (line 196) and the redundant `_mediaControlService.SetVolume(SelectedItem.Volume)` (line 195) — `PlayMedia` / `Play` in `MediaControlService` already applies the volume set on `_liveWindow`. Just raise `OnPropertyChanged(nameof(Volume))` and `OnPropertyChanged(nameof(VolumePercentage))`.
- **Note**: `SelectedItemVolumePercent` already reads from `SelectedItem.Volume` directly — no change needed.

### 2. `Services/MediaControlService.cs`
- In `PlayMedia`, the `itemVolume` parameter is **always** provided by `MainViewModel` (`SelectedItem.Volume`), so the fallback `?? _settings.MainMediaVolume` is dead code. Change the fallback to `_settings.DefaultServiceVolume` to be consistent with per-item semantics. Update the XML doc comment on the parameter to remove the `MainMediaVolume` reference.

### 3. `AppSettings.cs`
- **Remove** `public double MainMediaVolume { get; set; } = 0.5;`
- **Remove** `MainMediaVolume = Math.Clamp(MainMediaVolume, 0.0, 1.0);` from `Validate()`.

### 4. `ViewModels/LoadingPlaceholderViewModel.cs`
- **Change** `public double Volume { get; set; } = 0.5;` to use `AppSettings.Current.DefaultServiceVolume` as the initial value, so the placeholder slider position is consistent with the actual default. (Minor polish — not a correctness issue.)

### 5. No changes needed
- `LiveOutputWindow.cs` — `_targetVolume` / `SetVolume` / `Playing` event re-apply logic is correct and stays.
- `PlaylistManager.cs` — per-item volume on save/load is already correct.
- `MainWindow.xaml.cs` — `ViewModel.Volume` reads/writes will work correctly through the new computed getter. `VolumeUp` / `VolumeDown` / `SetVolume` via `IDisplayController` all go through `ViewModel.Volume` setter, which will correctly target the right item. `RecreateLiveOutputWindow` calls `_mediaControlService.SetVolume(ViewModel.Volume)` which still works.
- `MainWindow.xaml` — the volume `Slider` binding (`Value="{Binding Volume, Mode=TwoWay}"`) requires no change.

## Expected Behavior After Fix
- The volume slider always reflects the volume of the item that will be affected:
  - If media is playing → shows the playing item's volume; adjustments change the playing item.
  - If stopped but an item is selected → shows the selected item's volume; adjustments change the selected item.
  - If nothing is selected → shows `DefaultServiceVolume`; adjustments have no persistent effect.
- Switching items updates the slider automatically via `OnPropertyChanged`.
- No global volume state exists; playlist files and per-item volumes are the only volume data.

## Validation Steps
1. Add two items with different volumes (e.g., 100% and 50%).
2. Play item A; verify slider and audio match.
3. Stop, select item B, play; verify slider and audio switch to B's volume.
4. While item B is playing, select item A (without playing); verify slider stays at B's volume.
5. Adjust slider while B is playing; verify B's volume changes and A's volume is untouched.
6. Stop, select A, adjust slider, then play A; verify A uses the newly adjusted value.
7. Restart app; verify no master volume is restored and items retain their individual volumes.
